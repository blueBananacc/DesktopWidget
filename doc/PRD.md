# 收工牌 PRD

> 文档版本：0.2  
> 文档状态：产品概念稿 / 待用户验证  
> 产品形态：桌面 OLED 状态牌 + 手机 App（显示技术暂定为 OLED）  
> 目标版本：MVP  
> 更新日期：2026-10-31

## 1. 产品概述

### 1.1 一句话定义

收工牌是一款由用户本人控制的桌面状态牌，通过 OLED 屏表达当前是否方便被打扰，并通过“一键收工”帮助用户结束工作状态、回顾当天的状态分布。

### 1.2 产品背景与问题

在办公室或居家办公时，同事通常难以判断一个人是否方便沟通。用户需要反复解释自己正在专注、开会或准备下班；另一方面，工作结束时也缺少一个明确、轻量的收尾动作。

收工牌尝试解决两个具体问题：

1. 让用户以低成本、可见的方式表达当前工作边界。
2. 帮助用户明确结束当天的工作状态，并回顾自己设置过的状态。


## 2. 目标用户与使用场景

### 2.1 目标用户

- 经常在共享办公室、固定工位或居家办公的人。
- 需要长时间专注，且希望减少非紧急打扰的人。
- 希望用简单方式回顾工作状态，但不希望被效率监控的人。

### 2.2 主要场景

1. 用户开始专注工作，通过机身预设触摸位置或 App 切换至“专注中”。
2. 同事经过工位时查看桌牌，判断是否适合打扰。
3. 用户提前设置当天时间计划表，到达对应时间点后桌牌自动切换为计划状态，例如 9:00“工作中”、10:30“会议中”、13:00“工作中”。
4. 用户设置待办提醒，在桌牌上查看一条简短摘要。
5. 用户下班时长按收工键，结束当天状态记录并查看回顾。

## 3. 功能需求与优先级

优先级定义：

- **P0：**MVP 必须具备。
- **P1：**MVP 后或资源允许时实现。
- **P2：**暂不纳入近期计划。

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 桌牌展示当前状态 | P0 | 大字、图标和状态颜色/样式可快速辨认 |
| 机身电容触摸区域切换状态（暂定） | P0 | 触摸指定位置切换状态；触摸区映射待原型验证 |
| 一键收工 | P0 | 结束当前状态并生成当日回顾 |
| 手机 App 基础设置 | P0 | 配对、状态设置、同步和查看回顾 |
| 蓝牙同步与断连恢复 | P0 | 设备离线时保留当前状态，重连后同步 |
| 状态持续时间/到期提醒 | P0 | 防止状态长期未更新 |
| 时间计划表与定时状态切换 | P0 | 支持重复计划、单日计划及计划表切换 |
| 旋钮快速定时与休息提醒 | P1 | 旋钮按格调整时长；工作状态下默认每 45 分钟提醒休息 |
| 自定义实体快捷键、RGB 状态灯 | P1 | App 配置快捷操作；灯光可关闭或调低亮度 |
| 多设备共享状态看板 | P1 | 同区域设备间优先验证 ESP-NOW；App 看板汇总需网关转发 |
| 手机静音/专注模式联动 | P1 | 仅在操作系统授权和能力允许时启用 |
| 语音创建提醒、下班提示 | P1 | 通过手机网络调用云端 AI 解析，执行前可确认 |
| 自定义屏幕动画 | P2 | 先提供安全的模板/帧动画能力，再评估代码扩展 |
| 电脑 Agent 状态联动 | P2 | 通过电脑伴侣或 Agent 集成显示运行、待输入、完成/异常 |
| 个人云同步、同一账号多设备管理 | P2 | 与共享状态看板所需的联网服务区分，视用户验证和隐私方案规划 |

### 3.1 状态管理

#### 状态集合

MVP 提供以下预设状态：

- **工作中**正在工作，可以随时联系。
- **忙碌/勿扰**当前不希望被打扰，可由用户通过自定义快捷键快速开启。
- **会议中**正在参加会议或通话。
- **休息中**用户主动进入的休息状态；休息提醒本身不自动改变状态。
- **已下班**当天工作状态已结束。


#### 需求

- 用户可通过 App 选择状态。
- 设备端状态切换方式暂定为触摸机身预设电容触摸位置；触摸位置与状态的映射、单击/长触等交互规则在原型阶段验证后确定。
- 触摸位置指机身上的独立电容触摸电极，不代表 OLED 屏幕具备触摸屏功能。
- “会议中”状态可设置结束时间或持续时长。
- 到期后，设备提醒用户确认是否延长或切换；未经用户确认，不应默认推断其当前状态。
- 所有状态切换记录来源：设备电容触摸、实体快捷键、App 手动操作、时间计划表、旋钮定时或 Agent 集成。
- 状态更新后，App 与设备应在蓝牙连接时完成同步。
- 可以按需设置一定时间段的提醒

### 3.2 桌牌信息展示

#### MVP 展示内容

- 当前状态名称和易辨认图标。
- 状态预计结束时间（如已设置）。
- 可选的简短提示，例如“30 分钟后提醒”。
- 电量或同步状态仅在需要用户处理时显示。

#### 设计要求

- 以状态信息为视觉主层级，远距离也能快速辨认。
- 重要信息不依赖颜色单独表达，需配合文字或图标，考虑色觉差异。
- 默认不显示会议标题、参会人、地点及完整待办内容。
- OLED 长时间显示静态高亮内容存在烧屏风险，界面应避免不必要的全屏常亮元素，并结合降亮度、定时熄屏或像素位移策略缓解。
- 若加入状态灯，灯光应低亮、可关闭，并提供不使用灯光的模式。
- 支持用户自定义屏幕布局、静态图像及帧动画；动画不应影响状态名称、结束时间等核心信息的辨认。
- OLED 的显示尺寸、亮度、远距离可读性、烧屏缓解效果和功耗需经原型验证；单色小屏不承诺复杂动画效果。
- 支持通过 App 选择 RGB 灯光状态映射、亮度及关闭时段；状态灯闪烁只用于计时结束、Agent 需要输入等提醒，且可分别关闭。


### 3.3 时间计划表（计划日历）

本产品中的“日历”指用户自己创建和管理的**状态时间计划表**，不是读取外部日历后推断用户状态。用户提前指定某个时间点应展示的状态，到达时间后设备自动切换。

#### 计划表类型

- **重复计划：**例如工作日 09:00“工作中”、10:30“会议中”、11:30“工作中”、18:00“已下班”。
- **单日计划：**仅在指定日期生效，可用于当天临时日程；当日结束后不自动重复。
- 用户可创建多个计划表，例如“标准工作日”“居家办公”“周五短工作日”，并在 App 中一键切换当前计划表。
- 每个计划表由按时间排序的状态节点组成；每个节点至少包含开始时间、目标状态和可选提醒设置。
- App 需显示当前生效计划表、下一次状态切换时间和目标状态。

#### 自动切换规则

- 到达计划节点时间后，桌牌自动切换到该节点指定的状态，并记录来源为“时间计划表”。
- 可配置是否在切换时同步提醒用户；提醒不应要求用户确认后设备才更新状态。
- 用户手动切换状态时，按用户设置的覆盖规则生效：默认仅覆盖到下一个计划节点，用户也可选择“暂停今日计划”或“恢复计划”。
- 按下“一键收工”后，当日不再被后续工作节点自动切回工作状态；用户主动重新开始工作时除外。
- 同一时刻出现多个节点时，以用户最后保存的节点为准，并在 App 中提示冲突。
- 计划表按手机/App 设置的时区运行；时区变化、夏令时切换和手机离线等情况需在 App 中明确展示当前计划状态。
- 设备离线时应使用最近一次同步的计划表和本地时钟执行；重连后同步实际发生的状态切换记录，避免重复记录。

#### 验收标准

- 用户可创建、编辑、复制、删除多个计划表，并设定重复规则或单日日期。
- 到达计划节点后，设备在无需用户打开 App 的情况下自动显示对应状态。
- App 可一键切换计划表，并展示下一次自动切换的时间和状态。
- 手动覆盖、“暂停今日计划”和“收工”不会被后续计划节点意外覆盖。
- 无计划节点的时段继续保持上一个状态，直到下一个节点或用户手动切换。

### 3.4 待办与提醒

- 用户可在 App 中创建或编辑简短提醒。
- MVP 后续可先支持一条置顶提醒和今日提醒数量，不承担完整任务管理。
- 用户可设置是否在桌牌上显示提醒正文；默认对桌面访客隐藏敏感内容。
- 提醒到期后可在 App 中完成、延期或删除。
- 用户可通过语音或文本创建自然语言提醒，例如“今天下班后带狗狗看医生”；App 解析出时间和内容后应让用户确认，再同步至桌牌。
- 用户进入“已下班”状态时，可展示用户明确设置为下班后提醒的事项；提醒内容默认为仅本人可见。

### 3.5 一键收工

#### 交互定义

- 用户长按实体收工键（建议原型测试约 2 秒阈值）或在 App 中点击“收工”。
- 设备显示“已下班”状态。
- 当日状态记录在收工时结束；之后不再累计工作状态时长。
- App 展示当日状态回顾，并允许用户查看或修正记录。

#### 防误触与恢复

- 收工使用长按或明确的二次确认，避免误触。
- 收工后如需恢复工作，用户可手动切换状态；系统应提示这将开启新的状态区间。
- 收工操作应在设备端立即反馈；如手机未连接，先本地记录，重连后同步。


### 3.6 状态回顾

#### 展示内容

- 当日各状态的累计时长和占比。
- 未记录时段。
- 状态切换次数。
- 各状态区间的起止时间及来源。

#### 统计原则

- 不记录状态的时间显示为“未记录”，不推断为休息或工作。
- 用户可修正明显错误的状态区间；修正后保留统一的最终记录，避免误将推断值当作事实。
- 统计按手机本地时区和自然日展示；跨时区情况需以记录发生时的本地时间处理。

### 3.7 多设备互联与共享状态看板

- 用户可在 App 中选择是否分享自己的**当前状态**，并可随时暂停分享或撤销成员访问。
- 用户可通过邀请链接、二维码或区域/团队邀请码加入一个共享区域；状态搜索和看板仅限该区域成员，不提供默认公开的全局目录。
- 共享看板显示成员名称/头像、当前状态、可选的预计可联系时间及最后更新时间；用户自己的状态也显示在看板中。
- 成员状态变化后，已授权的看板应更新；状态历史、私人待办、计划表详情和日历内容不对其他成员开放。
- 分享范围和查看范围分别由用户控制：允许分享状态不自动代表允许加入任何区域；加入区域也不自动代表公开状态。
- 成员退出区域或取消分享后，其他成员不能继续查看其当前状态；已缓存状态应标记失效并在合理时间内清除。
- 设备或手机离线时，状态卡片显示最后更新时间；超过设定时限后标记为“可能已过期”，不得将旧状态伪装成实时状态。
- 同一区域内的设备间状态互通，当前优先考虑 ESP-NOW 局部无线广播；用户未开启分享时不得广播个人状态。
- ESP-NOW 广播用于设备间同步，不等于手机 App 可直接接收。若 App 看板需要汇总区域内成员状态，暂定由指定设备作为网关，通过 BLE 等方式把收到的状态列表转发给 App。
- ESP-NOW 的配对/区域识别、设备授权、消息保护、信道协调、离线过期时间及实际覆盖范围需经原型验证；不得将无保护的广播视为私密传输。
- 跨区域、远程查看或没有可用网关时，仍需 Wi-Fi/MQTT 或云端同步作为后续方案；首版是否支持需另行评估成本、账号和隐私方案。

#### 验收标准

- 用户能主动开启/停止分享、加入/退出共享区域，并能查看当前哪些成员可见自己的状态。
- 仅同一共享区域且满足分享授权的成员可互相看到状态。
- 共享看板可显示本人和其他成员状态及最后更新时间。
- 取消分享或退出区域后，其他成员不能继续获取新的状态；旧数据会标记过期或清除。

### 3.8 自定义实体快捷键

- 除“一键收工”外，增加一个可由用户自定义的实体快捷键。
- 用户可在 App 中将快捷键映射为预设动作，例如“开始工作”“切换为忙碌/勿扰”“开始专注倒计时”“进入休息状态”或启动某个用户定义的状态。
- 快捷键至少支持单击；如硬件支持，可配置长按或双击，但默认操作应保持简单并避免误触。
- 快捷键触发后，设备屏幕和状态灯立即反馈，App 记录操作来源。
- 用户可将快捷键恢复为默认配置；快捷键不得覆盖“一键收工”的安全确认规则。

### 3.9 手机静音/专注模式联动

- 用户可分别设置“工作中”“忙碌/专注中”等状态是否触发已配对手机的静音、勿扰或专注模式。
- 状态变化由设备通过 BLE 通知手机 App，再由 App 在操作系统授权范围内执行；联动失败不得阻止桌牌状态切换。
- 用户需明确授权并可随时关闭联动；开始前说明系统可能限制自动切换能力。
- 手机应记录联动前的模式，并在用户离开相应状态或收工时按用户设置恢复；若用户期间手动改变手机模式，恢复逻辑不得覆盖用户的手动选择。
- iOS、Android 对静音和专注模式的控制能力不同。无法直接切换时，应提供系统快捷指令、专注模式配置或 App 内通知静音等替代方案，不承诺绕过系统限制。

### 3.10 自定义屏幕内容与动画

- 用户可在 App 中选择布局、图标、静态背景/图片及状态页面样式。
- 后续版本支持有限时长的帧动画，例如时间滚动效果或简单角色动画；关键状态文字需保持常显或在动画帧中清晰可辨。
- 用户提出的“上传代码自定义动画”作为 P2 扩展能力：优先提供受限的动画描述格式、模板或沙箱化 SDK，不允许未经校验的任意原生代码直接在设备固件中执行。
- App/桌牌需对动画的分辨率、帧数、资源大小和播放时长进行限制，并提示其对烧屏和电池续航的影响。
- 对持续运动的动画优先使用 RGB 灯效；OLED 虽可流畅刷新，但长时间播放高亮动画会加速烧屏并增加功耗，不应以长时间动画作为核心体验承诺。

### 3.11 电脑 Agent 状态联动

- 用户可将桌牌与电脑伴侣 App 或受支持的 Agent 集成连接，在桌牌上显示 Agent 的概括状态。
- MVP 之外按 P2 规划；首批状态包括“Agent 运行中/Thinking”“需要新的输入”“已完成”“发生错误”。
- 用户可选择要显示的 Agent/会话；不显示 Prompt、代码、文件内容、仓库名或客户信息。
- 状态检测优先通过官方 API、CLI hooks 或本地伴侣程序；不得通过屏幕录制、键盘记录或读取无关应用内容实现。
- 电脑端状态可经 BLE、USB 或局域网传递给桌牌；连接中断时显示最后更新时间，超时后清除或标为未知。
- “已完成/需要输入/发生错误”可触发一次可关闭的 RGB 提醒；不应因 Agent 长时间运行而频繁闪烁。

### 3.12 RGB 状态灯

- 在屏幕周围集成可选 RGB 灯环/灯带，辅助远距离识别当前状态。
- 支持用户设置状态到灯色的映射、亮度、常亮/呼吸/闪烁模式及夜间关闭时段。
- 计时结束、休息提醒、Agent 需要输入等事件可使用短时闪烁；可通过按键或旋钮操作确认/停止。
- 屏幕文字和图标仍是状态的权威信息；颜色不可作为唯一信息通道。
- 设备可设置“无灯光”模式，以满足共享空间、夜间和对光敏感用户的需要。

### 3.13 旋钮快速定时

- 设备增加旋钮，用户旋转可快速设定倒计时时长；默认每格增加或减少 5 分钟，方向和反馈在原型测试中确定。
- 建议初始可设范围为 5–180 分钟，具体上下限可在 App 中调整。
- 旋转时屏幕显示当前选择时长；按下旋钮确认后开始计时，长按可取消或重置。
- 计时期间屏幕显示剩余时间和关联状态（如专注中）；计时结束时通过可配置的 RGB 闪烁、设备提示音或手机通知提醒。
- 计时结束后不自动推断用户状态；用户可选择结束专注、延长计时或继续当前状态。
- 旋钮定时与计划表节点同时发生时，以用户在 App 设置的优先级为准；默认定时仅控制倒计时和提醒，不改写计划表。

### 3.14 语音输入与云端 AI 提醒解析

- 设备提供麦克风，用户可语音创建定时或提醒，例如“提醒我今天下班后带狗狗看医生”。
- 语音经手机 App 转发到云端 AI 解析；手机是网络网关，设备不假设可直接访问互联网。
- 支持解析定时指令，例如“设置 45 分钟专注倒计时”，以及提醒指令，例如“提醒我今天下班后带狗狗看医生”。
- 解析结果至少包括动作类型、时长/触发时间或条件、提醒内容和展示方式；涉及时间不明确、跨日或动作有歧义时，必须先向用户确认。
- 用户确认后才创建提醒；AI 不得擅自修改计划表、切换共享权限或触发不可逆操作。
- 下班提醒可配置为在进入“已下班”时展示，也可配置为指定时间触发；如用户未收工，按其选择的触发规则执行。
- 语音录音仅为完成解析而临时处理，不默认保存原始音频；App 需明确告知云端处理、数据用途和删除方式。
- 提供物理麦克风关闭/静音方式及录音状态指示；用户可关闭云端 AI，仍可通过 App 手动创建提醒。
- 网络不可用时提示无法完成云端解析，并允许用户改用手动输入；不得静默创建错误提醒。

### 3.15 默认休息提醒

- 默认每累计 45 分钟处于“工作中/专注中”后提醒用户起身活动；用户可在 App 调整间隔、关闭或改为其他提醒内容。
- 累计时间仅统计工作相关状态，不通过传感器检测用户是否真的工作或是否起身。
- 进入“会议中”“已下班”或用户主动暂停时，休息计时默认暂停；会议结束后可继续剩余计时或重新开始，由用户选择。
- 提醒通过 RGB 灯、屏幕动画或手机通知中的已启用渠道发出；避免声音默认打扰他人。
- 用户可选择“稍后提醒”“今天不再提醒”或关闭提醒；提醒行为不改变工作状态，也不写入效率评分。
