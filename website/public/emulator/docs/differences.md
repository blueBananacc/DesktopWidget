# 模拟器与收工牌有何不同

收工牌位于你的网络上；模拟器运行在你工作的电脑上，与你自己的服务相邻。在涉及安全的地方，模拟器比收工牌更严格。本页先列出这些差异，然后列出我们已知的其他差异。这份清单并不完整：收工牌拥有最终发言权，所以在依赖某个细节之前，请先在收工牌上运行你的应用。

## 谁可以调用模拟器

| | 收工牌 | 模拟器 |
|---|---|---|
| 其他网站的网页 | 任何页面都可以调用收工牌的 API 并读取应答：每个应答都带 `Access-Control-Allow-Origin: *`。 | 以 `403` 拒绝。只有模拟器自己的页面（它的本地网页、它的窗口）可以调用。 |
| 你自己的页面，来自你信任的来源（origin） | — | 桌面应用没有放行网页的设置。让你电脑上的程序替页面发出请求（你的开发服务器、一个脚本）：没有 `Origin` 头的请求会得到应答。从模拟器源码启动的服务器（`node packages/server/index.mjs`）接受 `--allow-origin <origin>`（例如 `--allow-origin http://localhost:3000`），每个来源一次；此后该页面会得到与收工牌给出的相同的 CORS 头。 |
| `Origin: null` 的页面（沙盒中的 frame、从磁盘打开的文件） | 会应答。 | 以 `403` 拒绝。让你电脑上的程序发出请求，或者从某个网址提供该页面，并用 `--allow-origin` 把它的来源告知从源码启动的服务器。 |
| 以 `127.0.0.1` 或 `localhost` 以外的名字发来的请求 | 会应答：收工牌不检查 `Host`。 | 以 `403` 拒绝。这可阻止网站通过一个指向你电脑的自有域名访问模拟器（DNS 重绑定）。 |
| `localhost` 与 `127.0.0.1` | 同一台收工牌。 | 同一个模拟器，但从其中一个加载的页面对另一个来说是另一个来源，与在任何浏览器中一样。请调用页面来源的那个地址。 |
| 没有 `Origin` 的程序：`busy-cli`、`curl`、脚本、AI 代理 | 会应答。 | 会应答。它们得不到 CORS 头，但它们也不需要。 |

同样的规则适用于状态流 `ws://…/api/status/ws`。

其他来源的页面同样不能嵌入模拟的收工牌地址所给出的内容：每个应答都带 `Cross-Origin-Resource-Policy: same-origin`、`X-Content-Type-Options: nosniff` 和 `frame-ancestors 'self'`。因此别的页面既不能把本地网页放进 frame，也不能把收工牌存储中的文件作为脚本、图片或样式来加载。收工牌允许所有这些。对用 `--allow-origin` 指定的页面同样成立：它可以用 `fetch` 读取 API，但不能在自己页面上放 `<img src="http://127.0.0.1:8640/api/screen">`；请改为绘制 `fetch` 取回的内容。

## 收工牌上的应用可以访问什么

在收工牌上，`localhost` 就是收工牌自己：应用以 `http://localhost/api/...` 访问它所在收工牌的 API，`localhost` 的其他任何端口后面都没有东西。在模拟器中，同样的地址会指向你工作的电脑——那里有你的数据库、开发服务器和模拟器自己的管理地址。所以模拟器让应用远离你的电脑：远离它的回环地址，也远离它的其他网络地址。

| | 收工牌 | 模拟器 |
|---|---|---|
| `http://localhost/api/...`、`http://127.0.0.1/api/...` | 收工牌的 API。 | 模拟的收工牌的 API。 |
| `localhost` 的其他端口、`127.0.0.1`、`127.0.0.0/8` 的其余部分、`0.0.0.0` 或 `[::1]` | 收工牌本身，那里没有监听者：请求以 `socket error` 失败。 | 以同样方式失败，报 `socket error`，没有任何东西到达你的电脑。应用的控制台会说明原因以及如何放行该端口。 |
| `*.localhost`、`localhost.`、数字写法（如 `2130706433` 或 `127.1`）、解析到回环地址的域名 | 按固件的代码，收工牌会把这类名字交给 DNS（它自己只认识 `localhost` 和点分地址）；之后发生什么取决于网络。 | 同上，立即以 `socket error` 拒绝。 |
| 你电脑自己的网络地址：它在你的家庭网络上的地址、它的 IPv6 地址、VPN 的地址（如 Tailscale）、收工牌的 USB 网络、它在你路由器 DNS 中的名字 | 同一网络上的收工牌可以访问监听你电脑所有接口的服务（`app.listen(3000)` 不带主机名、Docker 发布的端口），如果你电脑的防火墙放行的话。 | 除非该端口被放行，否则以 `socket error` 拒绝。从你电脑内部，模拟器与你的服务之间没有防火墙，所以放行这些地址会向每个应用敞开收工牌原本只能穿过防火墙才能到达的东西。这些地址在每次请求时重新读取。 |
| 你放行的端口 | — | 可以到达，包括回环地址和你电脑自己的地址。在模拟器运行时执行 `busy-emulator allow-local <port>`（见下），或从模拟器源码启动服务器时加 `--allow-local <port>`（每个端口一次）。网页不能放行端口，模拟器自己的窗口也不行。 |
| 模拟的收工牌的地址（默认 8640）及其管理地址 | — | 永远拒绝，无论放行与否。 |
| 其他任何地址：互联网、你网络上的其他电脑 | 可以到达。 | 可以到达。 |

要在模拟器运行时放行端口——桌面应用会自己启动模拟器，情况相同——请使用模拟器的命令行。模拟器拒绝请求时，应用的控制台会给出命令名：

```sh
busy-emulator allow-local 3000            # apps may reach port 3000 of this computer until the emulator quits
busy-emulator allow-local --remove 3000   # not any more
busy-emulator allow-local                 # the ports allowed now
```

命令行位于 macOS 的 `~/.busy-emulator/bin/busy-emulator` 和 Windows 的 `%LOCALAPPDATA%\busy-emulator\bin\busy-emulator.exe`。它把服务器密钥发送到模拟器的[管理地址](#管理地址)。你自己的程序也可以用 `POST`、`DELETE` 或 `GET /_emu/local-ports?port=<port>` 加请求头 `Authorization: Bearer <key>` 做同样的事。

域名只解析一次，请求发往的正是检查过的那个地址，所以第二次应答另一个地址的域名（DNS 重绑定）无法通过。这些请求的收工牌错误文本取自其固件代码（lwIP 用 reset 应答收工牌上已关闭的端口，mongoose 报 `socket error`）。尚未在收工牌上验证过。

## 管理地址

除了收工牌的地址外，模拟器还监听 `127.0.0.1` 上的第二个端口——管理地址，用于收工牌没有的功能。它只应答发送了服务器密钥的程序：`Authorization: Bearer <key>`。模拟器每次启动都生成新密钥，写入其数据文件夹中的 `key` 文件，仅你的用户可读；它从不被打印。数据文件夹中的 `run/server.lock` 写有该地址，从源码启动的服务器会在第二行打印它。

## 日志会记录应用的哪些错误

模拟器会把一些应用错误记进它的日志（`busy-emulator logs`），而收工牌对这些秘而不宣。这些行以 `emulator:` 开头；应用看不到它们，像在收工牌上一样继续运行。

- 模拟器在日志中显示未处理的 promise rejection，附原因和来源；收工牌不显示。
- 模拟器在日志中显示应用被拒绝的 API 调用，附收工牌的错误文本；收工牌不显示。busy-lib 会把这样的应答变成 `TypeError: Expected a function`，因为收工牌的运行时没有 `Response.clone()`。
- 模拟器记录应用发往网络的、收工牌以应用可能意想不到的方式处理的请求，附地址和需要改什么：重定向（收工牌不跟随）；失败的请求，附其错误的含义（`"Inactivity timeout"`、`"Failed to establish TLS connection"`）；在中途停止的响应——此时 `reader` 得到 `{ done: true, value: <错误> }` 而不是错误；大响应之后不久因内存耗尽导致的崩溃，附响应大小；以及 `TextDecoder` 或 `TextEncoder`——收工牌的 JavaScript 没有它们。这些收工牌一概不提。
- 在模拟的收工牌关机时对它执行 `busy-emulator press` 会应答 `bar_off`；`--power-on` 会开机，如同收工牌上的按键。

## 我们已知的其他差异

- **收工牌的速度是建模出来的。** 你的应用的 JavaScript 花费的时间按它在收工牌上本应花费的时间计算——根据它所做的工作（运行的指令、占用的内存），按在固件 1.3.1 的收工牌上实测的速率折算，而不是按你电脑的速度。
- **当电脑非常繁忙时。** 模拟的收工牌跟随你电脑的时钟走时。当某个东西拖住模拟器（高负载的电脑、从睡眠中唤醒的笔记本、调试器）时，收工牌每次最多追赶半秒。停顿超过这个时长后，它的时钟随电脑的时钟跳变：那段时间的固件时钟节拍和动画帧被跳过，周期定时器——固件的或你的应用的——对它错过的所有周期只触发一次，然后从那一刻继续。收工牌从不会这样被拖住。请在电脑不忙时录制短片。
- **永不返回的循环。** 在收工牌上，应用的 JavaScript 有自己的线程：`for (;;) {}` 或 `while (!ready) {}` 这样的循环会卡住应用，屏幕保持原样，长按 Back 可以停止它。在模拟器中，应用的 JavaScript 与模拟器本身共享一个线程，所以按你电脑的时间 2 秒不返回后，应用会被停止——如同长按 Back——日志会说明原因；期间按下的按键被丢弃。这里的 2 秒相当于收工牌上的几分钟，所以在收工牌上能正常工作的应用不会被停止。永不结束的 promise 链也一样——比如一个立即启动下一个的 `.then()`：它在收工牌上同样会卡住应用的 JavaScript。请改用 `setTimeout` 等待。
- **每次启动都是刚开箱的收工牌。** 你安装的应用、它们的设置和数据在模拟器的两次启动之间保留。收工牌自身的设置（音量、名称、时区）不保留。
- **HTTPS。** 模拟器依据收工牌自己的证书颁发机构列表检查服务器证书——即其固件中的那份（Mozilla 的，2026 年 10 月版），而不是你电脑的或 Node 的。它的 TLS 库不是收工牌用的那个（OpenSSL，而非 mbedTLS），所以只提供 mbedTLS 所缺内容的服务器可能在这里正常而在收工牌上失败；我们尚不知道有这样的例子。https 应答不会早于收工牌 1.4 秒握手允许的时间到来，但随后响应体以你电脑的速度到达：大响应体在收工牌上要下载更久，那段时间没有建模。
- **带收工牌私有密钥的请求。** 收工牌用私有密钥为发往 BUSY 应用 API 的部分请求签名；模拟器没有。它用保存的答案自行应答天气预报，其他此类请求则不带密钥发送：[向外发送什么](network-and-disk.md#向外发送什么)。
- **状态灯。** Start / Pause 旁的两个 LED 在固件点亮它们时点亮：BUSY 计时器、亮度设置、配对，以及你的应用带 `led_notification_color` 的 `POST /api/display/draw`（全亮度闪三下，然后熄灭）。它们的亮度跟随收工牌的亮度设置；自动亮度在收工牌上跟随光线传感器，模拟器取一半。
- **没有 `10.0.4.20`。** USB 上的收工牌在 `http://10.0.4.20` 应答；模拟的收工牌在 `busy-emulator status` 打印的地址应答——默认 `http://127.0.0.1:8640`，除非端口被占用。在教程写 `10.0.4.20` 的地方使用该地址（`busy-cli ... --addr 127.0.0.1:8640`）；没有应用时 APPS 屏也会显示它。HTTP API 文档在它的 `/docs/` 下，与真机收工牌一样：`http://127.0.0.1:8640/docs/`，其中的 Try it out 可对着模拟的收工牌实际操作。
- **仅模拟器有。** `busy-emulator time advance` 让时间立刻流逝，`record` 制作短片，日志会记录更多应用错误（见上）。收工牌没有这些。
